## Example workflow

The following example shows a lightweight support intake flow that you can adapt for your own team. It uses a simple JSON payload, a form submission, and a response check.

<CodeGroup tabs="JavaScript,cURL,Python">
  ```javascript
  const ticket = {
    subject: "Domain renewal needs review",
    priority: "medium",
    department: "WRLD.host",
    details: "The renewal date is approaching and the customer needs confirmation."
  };

  const response = await fetch("https://api.example.com/support/tickets", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Authorization": "Bearer YOUR_API_TOKEN"
    },
    body: JSON.stringify(ticket)
  });

  const data = await response.json();
  console.log(data.ticketId);
  ```

  ```bash
  curl -X POST "https://api.example.com/support/tickets" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer YOUR_API_TOKEN" \
    -d '{
      "subject": "Domain renewal needs review",
      "priority": "medium",
      "department": "WRLD.host",
      "details": "The renewal date is approaching and the customer needs confirmation."
    }'
  ```

  ```python
  import requests

  payload = {
      "subject": "Domain renewal needs review",
      "priority": "medium",
      "department": "WRLD.host",
      "details": "The renewal date is approaching and the customer needs confirmation."
  }

  response = requests.post(
      "https://api.example.com/support/tickets",
      headers={
          "Content-Type": "application/json",
          "Authorization": "Bearer YOUR_API_TOKEN"
      },
      json=payload
  )

  print(response.json()["ticketId"])
  ```
</CodeGroup>

## Common fields

When you document a service workflow, define the important fields clearly so readers know what to send and what to expect.

<ParamField path="ticketId" param-type="string" required="true">
  Unique identifier returned when a support request is created.
</ParamField>

<ParamField query="department" param-type="string" required="false">
  Limits results to a specific WRLD division such as support, hosting, design, or AI.
</ParamField>

<ParamField header="Authorization" param-type="string" required="true">
  Bearer token used to authenticate requests to the API.
</ParamField>

<ParamField body="details" param-type="string" required="true">
  A concise description of the issue, request, or workflow context.
</ParamField>

## Best practices

Use the checklist below to keep your documentation helpful and easy to maintain.

- Write for the person completing the task, not for the internal team that already knows the workflow.
- Prefer direct language and short steps when the process is routine.
- Keep links consistent and point readers to the smallest useful page.
- Use one example per workflow so the page stays focused.
- Validate every external endpoint in a staging environment before you publish instructions.

<Callout kind="tip">
  When you explain a workflow, include the reason for each step. Readers are more likely to follow a process when they understand why it matters.
</Callout>
